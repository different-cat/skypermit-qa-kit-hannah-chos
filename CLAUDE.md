# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Призначення

`skypermit-qa-kit` — QA-кіт для проєкту **SkyPermit** (система реєстрації операторів дронів, пілотів і повітряних суден та подання/розгляду заявок на польоти в зонах повітряного простору).

Основна робота в цьому репозиторії — **генерація тест-кейсів і тест-планів для мануального тестування** на основі документації SkyPermit. Автотести, код застосунку та зміни в самому SkyPermit тут не пишуться.

## Джерело вимог: `../skypermit` (тільки читання)

Проєкт SkyPermit лежить поруч, у `../skypermit`. Вимоги беруться з `../skypermit/docs/`:

| Файл | Що там |
|---|---|
| `01-data-model.md` | сім сутностей, поля, enum-и, похідні та збережені значення |
| `02-state-machine.md` | сім станів `FlightRequest` і дозволені переходи; будь-який інший перехід → `409` |
| `03-api-contract.md` | ендпоінти `/api/v1`, статус-коди, тіло помилки `422`, автентифікація |
| `04-frontend-spec.md` | два портали (ролі), сторінки, контракт `data-testid` |
| `05-open-questions.md` | канонічний статус кожного відкритого/закритого питання |
| `06-business-rules.md` | логіка гейтів, пороги, каталог зон |
| `07-clarifications.md` | відповіді власника бізнес-правил |
| `08-uml-diagrams.md` | згенеровані Mermaid-діаграми (похідні від 01 і 02) |

Пріоритет джерел, коли документи суперечать один одному:
- `07-clarifications.md` переважає `06-business-rules.md`.
- `06-business-rules.md` — це компіляція; якщо вона розходиться з першоджерелом, на яке посилається, правильним вважається першоджерело.
- Поточний статус питань береться **тільки** з `05-open-questions.md`. Для вимог, які ще не вирішені, тест-кейси позначаються як заблоковані або такі, що потребують уточнення. Очікуваний результат для них не вигадується.
- `08-uml-diagrams.md` похідний; якщо він розходиться з 01/02, правильними вважаються 01/02.

`../skypermit/CLAUDE.md` теж можна читати: там є загальний огляд і рекомендований порядок читання docs.

### Що заборонено робити з `../skypermit`

- Створювати, редагувати, перейменовувати чи видаляти будь-які файли в `../skypermit`, включно з `docs/`, `CLAUDE.md` і `AGENTS.md`.
- Виконувати там git-операції, які щось змінюють (`commit`, `checkout`, `stash`, `reset`, `pull`, `branch` тощо). Можна тільки читати (`log`, `show`, `diff`, `blame`).
- Запускати там `npm install`, `npm run dev`, `build`, `test` чи інші команди, що створюють або змінюють файли (`node_modules/`, `.next/`, кеші).
- Застосовувати міграції або будь-як звертатися до Supabase зі `supabase/`.
- Читати `.env.local` чи інші файли з секретами.

Якщо для тест-кейсу треба щось змінити в SkyPermit (помилка в docs, суперечність, прогалина), не виправляй це, а зафіксуй як знахідку чи питання в цьому репозиторії.

## Структура (планується)

```
test-cases/        # згенеровані тест-кейси та тест-плани (Markdown)
.claude/skills/    # скіли Claude Code для генерації тест-кейсів/планів
```

Обидві директорії поки що не створені. Коли з'являться формат тест-кейсу, конвенції іменування та скіли, опиши їх у цьому файлі.

## Принципи генерації тест-кейсів

- Кожен тест-кейс посилається на джерело: файл і розділ у `../skypermit/docs/`, з якого випливає очікуваний результат.
- Очікувані результати беруться тільки з документації. Вигадувати поведінку, якої docs не описують, не можна: така прогалина фіксується як відкрите питання.
- Для UI-кроків використовуй назви сторінок і елементів із `04-frontend-spec.md`.
